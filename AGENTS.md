# Working on This Project

- Read `docs/PROJECT_STATUS.md` at the start of a resumed session and verify the
  actual source and Git status before continuing.
- Update that checkpoint at meaningful milestones and before pausing: record
  changed files, actual checks and failures, unresolved work, and the exact next
  step. Save useful partial work to disk throughout the session.
- Preserve user changes and distinguish guide/web checks from FPGA evidence.
  Claim simulation, synthesis, timing closure or hardware results only with logs.
- The guide runs locally from `guide/`. After changing its structured research
  data, run `npm run handbook` and retain the generated handbook and ledger.
- Keep generated output, installed dependencies, credentials, private transcripts
  and employer material out of commits. Stage the intended files explicitly.
- For a requested push, verify the remote and authenticated account. Preserve the
  user's intended author identity and use a normal push; do not rewrite history.
